# 佳明路书纠偏器 · Garmin Course Fixer

把佳明（Garmin）课程／路书里的**"火星坐标"（GCJ-02）偏移**一键换算回真实 **WGS-84**，解决骑行／徒步时 **"路书漂移"、"一路提示回到道路"** 的问题。

单文件网页工具，双击即用，**纯本地运行**：文件不出电脑，原文件不被修改。

> 起因：中国大陆的合规地图（高德／腾讯／佳明中国地图）按法规使用加密过的 GCJ-02 坐标，而 GPS 芯片、佳明手表／码表自己记录的活动、两步路导出的 GPX 都是真实的 WGS-84。两者在昆明一带相差约 **南 331 m、东 142 m（合 ≈365 m）**。
> 在"中文地图"上生成／描线的路书，文件里会写死 GCJ 坐标；装到设备上后，设备拿你的真实位置（WGS-84）去比对，线就整体偏东南 ≈365 m ⇒ 一直提示"回到道路"。

## 功能

| 功能 | 说明 |
|---|---|
| 支持格式 | `.fit`（佳明课程／路书，含 course/lap/record 坐标）、`.gpx`（两步路等导出，含 trkpt/rtept/wpt） |
| 自动判定 | 联网抓 OpenStreetMap 真实路网，自动判断这条线是 **加偏 GCJ-02** 还是 **正常 WGS-84**（给出 A/B 中位差） |
| 一键纠偏 | GCJ-02 → WGS-84（最常用）、WGS-84 → GCJ-02（反向，贴中文地图用）、只检测不改 |
| 地图核对 | 内嵌地图（Esri 影像／Esri 街道／OpenTopoMap 地形／OSM 德国镜像，可下拉切换）：红线＝原始，绿色实线＝处理结果，绿色虚线＝"如果纠偏后"的预览；支持多文件同屏（选中高亮、点表格行切换）；拖动/滚轮与手机地图一致 |
| 安全 | **原文件永不改动**，结果另存为 `原名-WGS.fit` / `原名-gcj02.gpx`；FIT 只改坐标字段，其余字节原样，CRC-16 重算 |
| 批量 | 一次拖入多个文件，全部处理后一键下载 |

## 快速开始

1. 下载本仓库，双击打开 `index.html`（Edge / Chrome 均可）。
2. 把 `.fit` 或 `.gpx` 拖进页面。
3. 处理方式选 **自动判断** → 点「开始处理」。表格会显示判定结果，例如 `加偏 GCJ-02（A=101.9m / B=3.8m）`。
4. 点「下载」拿到纠偏后的文件，拷进设备：
   - USB 连接设备 → 打开 `Garmin\NewFiles`（或 `Garmin\Courses`）→ 拷入 → 拔线后**设备关机再开机**，路线／课程列表里就会出现；
   - 或导入 Garmin Connect 网页（训练 → 路线 → 导入）再同步。
5. 确认新课程可用后，把设备上原来那条"加偏"的课程删掉，避免混淆。

## 底图源与最大放大级别

| 底图源 | 最大级别 | 说明 |
|---|---|---|
| **Esri 影像（默认）** | 19 | 卫星影像，全球覆盖，看"线有没有压在道路上/轨迹上"最直观 |
| OSM 德国镜像 | 19 | 标准 OSM 风格，街道级可放大 |
| OpenTopoMap 地形 | 17 | 等高线 + 地形，适合户外路线 |
| Esri 街道 | 16 | 街道图在中国只到 16 级左右，再放大是占位瓦片（工具到顶会提示换源） |

> 所有内置底图都是**真 WGS-84 参考**——像高德/腾讯那种 GCJ 口径底图会把线整体带偏 365 m，不能用来核对。

绿色线的含义：**实线＝真的生成了纠偏结果；虚线＝"假如纠偏会变成什么样"的预览**。判定为"正常 WGS-84"的文件不需要纠偏，此时虚线只是给你看的对照。

## 判定原理

把轨迹按点密度切成几个 0.01° 窗口，抓该窗口的 OSM 路网，然后分别计算两种假设下"点到最近道路"的距离中位数：

- **假设 A**：文件里的坐标就是真实坐标（WGS-84）
- **假设 B**：文件里的坐标是 GCJ-02，先换算回 WGS-84

哪个假设的中位差小，文件就是哪一套坐标系。实测（同一台码表上的 10 条真实课程）：

| 课程 | A（当作 WGS） | B（当作 GCJ） | 判定 |
|---|---|---|---|
| 环草海融创 | 23.6 m | **2.0 m** | 加偏，需纠偏 |
| 230小河 | 101.9 m | **3.8 m** | 加偏，需纠偏 |
| 777骑行_1月_24 | 27.0 m | **0.6 m** | 加偏，需纠偏 |
| 231新滇池绿道环滇 | 34.3 m | **6.3 m** | 加偏，需纠偏 |
| 黄龙箐-哈马者环线 | **3.8 m** | 60.4 m | 正常 |
| 昆明市_公路骑行 | **5.3 m** | 31.5 m | 正常 |
| 469融创绿道 | **2.9 m** | 24.0 m | 正常 |
| 172安宁-青龙峡-豹子箐 | **2.4 m** | 27.6 m | 正常 |

纠偏后复验：中位差 **0.6–5.7 m**，5 m 内占比 38–100 %（纠偏前 8–12 %）⇒ 线路落在真实道路上。

## 命令行版（批量／脚本）

`python/fit_shift.py` 是同一套算法的 Python 实现（无第三方依赖，仅标准库）：

```bash
python fit_shift.py 输入.fit 输出.fit g2w --rename "新课程名"   # GCJ-02 → WGS-84
python fit_shift.py 输入.fit 输出.fit w2g                        # WGS-84 → GCJ-02
python fit_crc_check.py 输出.fit                                 # 校验 FIT 尾部 CRC
```

## 已验证

- 网页版与 Python 版对同一批文件（5 条真实课程，共 12 081 个坐标点）的纠偏结果**逐字节一致**，CRC 全部校验通过。
- GPX 通道：1371 点轨迹加偏后逐点位移 **363.0 m**（南 331 / 东 142），往返换算误差 ±1 量化单位（≈0.3 m）。
- 真实病例：码表上一条在 Connect 中文地图上生成的路书，骑行时"出门就提示回到道路"；判定为加偏（A=34.3 m / B=6.3 m），纠偏后中位差降到 5.7 m。

## 常见问题

**Q：为什么判定要联网？**
A：离线无法知道"真实位置应该在哪"，必须有一个真实坐标参考（这里用 OSM 路网）。不想联网就手动选「强制 GCJ→WGS」或「强制 WGS→GCJ」，再用地图核对（地图也需要联网）。

**Q：纠偏后线还是没压在马路中间？**
A：中文合规底图本身就是 GCJ 口径。设备若按真实坐标绘制，线与你（定位）一致，但可能和底图上的道路差 ≈365 m——这是显示层现象，不影响导航判定。

**Q：会不会把文件改坏？**
A：FIT 只改写位置字段的 4 字节数值（record #0/#1、lap #3~#6、course_point #2/#3 等），其他字节原样保留，末尾 CRC-16 重算；GPX 只改写 `lat/lon` 属性文本。原文件不动。不放心可以先跑"只检测、不改"。

**Q：支持哪些设备？**
A：凡是用 `.fit` 课程（Garmin Edge / fenix / Forerunner / Instinct 等）或 `.gpx` 路书的设备都适用。工具不依赖设备型号，只处理文件坐标。
